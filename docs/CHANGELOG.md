### Fixed

- （第二轮）**`saveUnits` 全删重建导致单位 ID 漂移**：原实现先删该规格下所有单位再重建，
  单位 ID 每次都变 —— 历史明细的 `unit_id` 随即失效，那张单再保存会被三元组校验打回。
  改为按单位名「比对后增删改」保留 ID（`saveSpecs` 同理，优先按回传的 `id` 匹配）。
- （第二轮）**`bind.IntQuery` 非法值静默返回 0**：`?categoryId=abc` 过去会被当成「不筛选」，
  等于放大了查询范围。现在非法值返回 40000。
- （第二轮）**`GET /inv/inventory` 的 `pageSize` 被硬编码为 200**：分页参数失效，超出部分看不见。
- （第一轮）**打印纸面不再出现「到期日」**。它是内部结算字段，打印版式（`printConfig`）里
  没有这一项、模板设计器也不提供，但 `OrderSheet.vue` 之前按「有值就打印」输出，
  于是未填写的单据会因为零值时间被打出一行「到期日：0001-01-01」——
  **模板里没有、纸面上却有**。
- （第一轮）**到期日零值收敛**（三道防线）：`InvOrder.DueDate` 由 `time.Time` 改 `*time.Time`
  （列改可空，空串落 `NULL` 而不是 `0001-01-01`）；启动时幂等修补存量零值
  （`database.PatchData()`，本机修正 4 行）；逾期判定的 SQL 侧补
  `due_date IS NOT NULL AND due_date > '1900-01-01'` 兜底。
- （第一轮）**逾期汇总与明细口径打架**：汇总 SQL 未排除零值到期日、行级有 `IsZero()` 守卫，
  同一页上「逾期金额」比逐行逾期之和大一截。现在两处共用同一口径
  （SQL 常量 `dueDateOverdueCond` + Go 侧 `isOverdue()`），冒烟脚本断言二者相等。
- （第一轮）**库存查询缺「单位」列**：单位原本拼在库存数字后面（`120 张`），容易被当成数量的一部分。
  现单列一栏，库存列只留数字。
- （第一轮）**单据明细选商品带出单位**：商品下拉显示「名称 规格（单位）」，明细行内单列「单位」栏。
- （第一轮）**品类占比饼图不渲染**：`EChart.vue` 只注册了 Line / Bar 系列，数据概览与报表中心
  的 pie 系列被 ECharts 静默丢弃（控制台一条 warning，图长期空白）。补注册 `PieChart`。

### 三、审查与易用性（第三轮）

对全项目做了一轮 bug 与逻辑审查，并顺带优化进销存的操作路径。

#### Fixed — 越权（P0）

- **跨业务线的写操作越权**：`/inv/orders` 路由的 `RequirePerm` 是「采购或销售任一」，
  handler 里的业务线二次鉴权只检查「持有 `inv:<bizType>:` 前缀的任意权限」。
  于是持有「`inv:purchase:list`（采购只读）+ `inv:sales:finish`（销售审核）」的账号
  **可以审核 / 删除采购单** —— 越权不需要绕过中间件，只要权限码拼得够巧。
  现在读路径仍走宽松口径，写路径改为比对完整的 `inv:<bizType>:<action>`
  （`ensureBizPermAction`）。冒烟新增「采购只读 + 销售审核」账号的越权矩阵断言。

#### Fixed — 并发（P1）

- **并发审核会重复过账**：`OrderChangeStatus` 在事务外读状态、判「不是已审核就放行」，
  两次并发都会读到「待处理」，于是生成两张出入库单、扣两次库存，
  而界面上只看到一张单。改为**条件更新** `WHERE id = ? AND status <> ?`
  并放在事务最后，`RowsAffected == 0` 即回滚整个事务。
- **并发作废会重复回滚库存**：`StockOrderVoid` 同样问题，改法同上。

#### Fixed — 静默的错误结果（P1）

- **`ProductPick` 静默截断**：一次最多 500 个商品，超出的不返回也无提示，
  用户只会以为「系统没录这个商品」。返回体改为 `{ items, total, truncated }`，
  前端 `truncated=true` 时提示「请用关键字搜索」，并把 `el-select` 接上
  `remote` + `remote-method`（服务端结果**合并**进本地列表，不替换 ——
  替换会让已选好的行找不到自己的 specId、显示成空白）。
- **模糊搜索未转义 `%` `_`**：搜「`M12_40`」会连「`M12X40`」一起出来，
  搜「`50%`」等于搜 `50` 开头的一切；结果既不报错也不为空，只是**不是你要的那批**。
  12 处 `ILIKE` 统一走 `likeKW()` 转义 + `ESCAPE '\'`。

#### Fixed — 数据一致性（P2）

- **停用挡不住**：`resolveSpecUnits` 只校验三元组存在、不校验状态，
  页面打开后管理员停用档案这段竞态里，库存仍会记到已停用规格上。
  现在三层（商品 / 规格 / 单位）都必须启用，错误信息点名是哪个。
- **规格名可带首尾空格**：`saveSpecs` 按 trim 后的名字比对、却写入未 trim 的值
  （`saveUnits` 一直是 trim 的，两处不一致）。统一写入 trim 后的值。

#### Changed — 易用性

- **商品筛选的分类下拉改为全量**（含已停用）：只给启用分类的话，
  分类一停用，属于它的那批商品就再也筛不出来 —— 筛选器变成「看起来正常但永远筛不到」。
  表单里的下拉仍只给启用项，但会把当前值补回去（改为在打开弹窗时缓存，
  不再依赖列表行还在不在 —— 翻页后就拿不到了）。
- **规格可以单独启用 / 停用**：被单据引用过的规格删不掉只能停用，
  此前没有这个开关，想让它退出新单据却无从下手。
- **分类删除不再让用户去撞 409**：引用数 > 0 时直接弹窗说明为什么不能删、
  该怎么做（移走商品或改为停用），而不是弹确认框让人点了才被拒。
- **单据与出入库明细的商品下拉支持远程搜索**（输入编码 / 名称直接搜）。

### 四、第四轮补扫（同类问题继续揪）

上一轮按「越权 / 并发 / 静默错误」三条线排查后，又补扫了一遍，发现并修掉 4 处
**同一条线延伸出来的漏网之鱼**：

- **[并发] 登记收付款也会超额结算**：`Settle` 与审核同病 —— 事务外读 `settled_amount`
  校验，两个并发登记都通过，累加后 `settled_amount` 顶破 `total_amount`。
  改为事务内条件更新 `settled_amount + ? <= total_amount + 0.001`，0 行即回滚。
- **[静默错误] 客户搜索漏了通配符转义**：上一轮 `replace_all` 只命中供应商分支
  （缩进不同），客户分支仍是裸 `ILIKE`。已补上，并加冒烟断言钉住
  「两条业务线的搜索口径一致」。
- **[口径不一致] 概览预警数把停用商品算进去**：`WarnProductCount` 只查规格表、
  没联商品状态，商品停用后其规格仍可能留在启用态被计入。改联表过滤启用商品。
- **[口径不一致] 商品列表展开行的预警不排除停用规格**：`buildSpecVOs` 的 `Warn`
  未看规格 `status`，与 `Inventory` / 概览口径不一致。统一为「启用才预警」。

接口冒烟 203 → **205 项断言**（客户搜索转义、登记收付款超额被拒）。

### 五、商品分类多级化 + 报表筛选 + 打印设计器扩展

#### Fixed — 分类树的操作按钮「存在但看不到」

- 删除按钮**代码一直在**，但做成 hover 才显形，而 `.cat-node` 用了
  `width: 100%` —— el-tree 的节点内容区前面还有展开箭头与层级缩进，
  内容区比容器还宽，三个按钮被推出可视区裁掉，**hover 也够不到**。
  用户看到的结论就是「没有删除功能」。
- 改用 `flex: 1` + `min-width: 0`，并让三个按钮**常显**（含删除），
  压掉 Element 相邻按钮的 12px 默认间距。删除按钮本就带就地拦截
  （有子分类 / 下有商品时弹窗说明原因），现在终于能点到。

#### Fixed — 开单商品下拉的「搜索没生效」

- 之前用 el-select 的 `filterable` + `remote` + `:remote-method`，
  把服务端结果**合并**进选项。但 **`remote` 模式下 el-select 不做本地过滤**，
  原样显示全部 options —— 请求发了、数据回来了，下拉却毫无变化，
  看起来就是搜索失效。
- 改为 `filterable` + `:filter-method`，过滤逻辑自己维护：
  - 匹配**名称 / 编码 / 规格**三字段（现场报「φ20」比编码更常见），
    与后端 `ProductList` 关键字口径一致；
  - **已选中的商品始终留在选项里**：el-select 靠 options 反查 label，
    丢出列表就会把「热轧钢板」显示成数字；
  - 选中后与打开下拉时都重置回全量，避免「输入框空了、列表只剩几条」的错位。
- 采购单、销售单、出入库单三处明细共用同一套逻辑。
- `pickLimit` 500 → **1000**：本地过滤靠一次性加载，选项太少会让
  「搜不到」变成家常便饭；1000 个 option 的渲染在几十毫秒量级，
  换来的是不用每次按键都发请求。超出时顶部照旧提示，不静默少给。

### 七、商品表单分类下拉可搜索 + 明细商品列加宽

用户反馈两条：① 新建商品的方式搜索和销售一样；② 销售和采购的商品名称框太小，加大。

#### Fixed — 商品表单的分类下拉「选不到子分类」

- 分类多级化之后，把树结构（带 `children`）直接喂给 `el-option` 的 v-for，
  **只渲染根节点** —— 子分类静默消失。「钢材 / 螺纹钢」这类子分类
  在录商品时根本选不到，而下拉看着完全正常（只是少了几项），肉眼极难发现。
- 改为**扁平化 + 层级路径**（`钢材 / 螺纹钢`），子分类回归列表。
- 顺带加上 `filterable`：label 是完整路径，输入「钢材」或「螺纹」都能命中，

### 八、规格单位改为可留空（自动兜底）+ 弹窗尺寸统一

用户反馈两条：① 单位和规格优化简化一下，不需要必须；② 各个弹出页面要大一点，
并样式统一，界面简洁。

#### Changed — 规格与单位从「必填」改为「可留空，缺了自动补」

- 原来的硬约束有四个：至少一个规格、每个规格至少一个单位、恰有一个基本单位、
  基本单位换算率恒为 1。录入一个「办公用品-签字笔」得先把这些想清楚。
- 现在这四个都不必填，服务端 `normalizeSpecs` 兜底：
  补「默认」规格、补「个」基本单位、把第一个单位提为基本单位、
  把基本单位换算率钉成 1；单位名为空补「个」、换算率 <= 0 补 1、空规格名补「默认」。
- **刻意不是「允许为空」而是「自动补」**：规格是库存的归属层、单位是单据折算的
  基准 —— 真留空的话商品会进不了开单的商品下拉（`ProductPick` 只给有规格的商品），
  等于建了个查不到、开不了单的僵尸档案。约束删不得，但也不该甩给用户。
- **唯一保留的硬约束是「不能重名」**：两行「φ20」会把库存劈成两半、各自都不预警；
  同一规格下两个「箱」会让单据选单位时不知道看哪一行的价格。
  两个都不填规格名的规格也会被判重名（都会补成「默认」）。
- 前端 `validateSpecs` 同步放宽，只查重名；嵌套的 `required` 规则去掉；
  提示语改为「选填，留空按『默认』/『个』处理」。

#### Changed — 弹窗尺寸分四档统一

- 此前 19 个弹窗用了 19 个不同宽度（420 / 480 / 520 / 560 / 600 / 620 / 640 /
  680 / 720 / 860 / 900 / 960 / 1000 / 1180 …），同一系统里点开不同弹窗宽度乱跳。
- 归为四档：**640**（简单表单）/ **800**（常规表单）/ **1100**（商品档案等网格表单）/
  **1280**（带明细表格、双栏布局、打印预览）。
- `top` 统一 `6vh`（打印类 `4vh`）。
- `styles/element.scss` 里给 `.el-dialog__body` 加**统一的最大高度 + 内部滚动**
  （`max-height: calc(100vh - 240px)`）—— 此前只有打印预览写了，别的弹窗在矮屏上
  会把底部按钮顶出视口；再加 `max-width: calc(100vw - 32px)` 保证窄屏不溢出。

#### 测试与文档

- 冒烟 **213 → 214 项**：原来断言「缺规格 / 缺单位 / 缺基本单位 / 换算率错
  返回 40000」的五条，改为断言**被兜底成什么**
  （「不填规格与单位 → 自动补成『默认 / 个』且为基本单位」等），
  并新增「多个基本单位只保留第一个」「两个都不填规格名判重名」。
- 浏览器验证 **76 → 78 项**：新增「开单弹窗宽度归到 xl 档（1280px）」与
  「商品档案弹窗宽度归到 lg 档（1100px）」—— 尺寸跑偏靠肉眼发现不了。
- `AGENTS.md` 新增 §5.86–§5.87（必填项该不该存在，先问「不填会怎样」；
  弹窗尺寸要分档统一 + 主体统一给最大高度）。
- `GUIDE.md` 新增 `3.8.3 弹窗尺寸与表单规范`；商品档案章节补规格单位可留空的说明。
