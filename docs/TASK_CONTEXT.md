# 采购编辑与合同核对交互

2026-10-28。依据 Goodwin 的任务连续性、Hodent 的注意与恢复原则，以及 Refactoring UI 的动作层级，调整三个场景。

## 体验入口

- 采购工作台点击“新增采购单 / 编辑采购单”，进入独立编辑视图。顶部返回原工作区；底部保留合计、取消、保存。URL 保留列表筛选及编辑模式，刷新重新读取相应单据，不恢复未保存草稿。
- 合同详情点击某期“流水”或“记录”，在付款计划下方查看，计划仍可对照。可切换期次、切换记录类型、失败重试或收起；收起后焦点返回入口。
- 采购、商品与合同的未保存修改统一保护。合同付款计划也包含在检测内。继续编辑保留输入，放弃后离开；无修改和正常保存不多问。应用内刷新和关闭当前标签尊重同一保护。

cd frontend

本次单元测试 53 项通过。浏览器专项：采购工作台 24、审核 6、下游交接 8、新增任务场景 8，共 46 个场景；类型检查及生产构建通过。新专项涵盖浏览器后退取消、应用内刷新取消、关闭标签取消、筛选与焦点恢复、编辑地址刷新、深链权限、加载失败、窄屏/暗色、合同计划关闭保护与保存失败、页内流水重试、跨合同迟到响应隔离。CI 执行上述四套浏览器脚本并上传证据。

浏览器脚本使用 Mock/确定性测试 API。合同期次流水在现有 Mock 中尚不支持，新专项为该接口显式提供测试夹具；不证明真实后端的库存或财务事务。旧 `interaction-verify.mjs` 需要真实后端和其固定 CDP 环境，本轮未通过该环境验证。静态严格审计仅保留既有 TagsView 的 ElDropdown 触发按钮误报（动作由父级管理），未为扫描器增加空点击处理。

## 视觉精简补充

采购顶部帮助区改为有错误/缺资料时才显示，资料入口分布到供应商与明细旁，保存影响放在底部。新建保留自定义编号，采购数量附带折算说明，合计只强调一次。合同用紧凑金额摘要和可折叠的履约/验收/质保信息替换大网格，付款计划合并列；触发节点、备注、审计 IP 均可展开回查。专项浏览器脚本已补充自定义编号焦点、唯一合计、合同信息展开、计划展开和审计 IP 查看断言。

视觉精简本轮验证：53 项单元测试、采购 24 个浏览器场景与任务场景 8 个均通过，类型检查和生产构建通过。旧交互脚本已尝试执行，因固定真实后端地址 127.0.0.1:6085 不可用（ECONNREFUSED）未完成，未计入通过项。静态审计仍仅有上述既有误报。
